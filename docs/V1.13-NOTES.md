# v1.13 — 文件式当面待办、13 种材料、条件链与模块化关卡编辑器

这一版把行政待办从“全天可点的纸堆”改成“轮到学生时当面递材料”，把原有 9 份待办升级为带纸张样式的学生文件，并新增交换生、实验室使用、实习推荐 3 份事件，共 12 份。根据最新反馈，待办不再占用独立面板：它和该学生的其他材料一样，是“其他材料”栏里可拖出/拖回的文件，批准/退回只在该文件内部。完整方案见 [`V1.13-SOLUTION.md`](V1.13-SOLUTION.md)。

---

## 1. 当面办理

- 待办绑定到关卡队列位置：`applicantId` 为主，`applicantIndex` 仅作旧数据回退。
- 学生轮到窗口时 Toast 提示：“轮到 X：材料已放入「其他材料」”；不再自动弹出大面板。
- 每份材料都是“其他材料”栏里的文件卡，和开题报告等常备附件同一套交互：
  - 点击或从卡上拖到桌面 → 打开纸张窗口；
  - 拖回材料架 / 点归档 → 收起，任务不办结；
  - 队列姓名旁有红色“待”标。
- **批准 / 退回在待办文件内部**：材料包第一份（申请表/请假条/推荐表）就是待办文件，底部有办理依据和两个按钮；其他材料窗口只供阅读。
- 没办结时，盖章 / 下一位 / 下班都会被拦下并重新打开待办文件。
- 办结后所有材料窗口收走，材料栏恢复常备附件，才能继续下一位。
- D4 / D7 的多个待办分别挂在不同的队列位置；前一位不会提前看到后一位的材料。

- **取消独立待办面板**：不再在左下新增“今日待办”面板。

- 右侧“其他材料”统一列出学生当面材料 + 常备附件：

  - 第一份卡带红色“待办”角标，其余材料带纸张/页签；
  - 栏内可滚动，不再挤掉开题报告等旧附件。
- 待办文件窗口（`RequestDesk._open_request_doc_window`）：
  - 与常备附件窗口同一套木质标题条、归档按钮和拖拽手感；
  - 520×500，正文由 `RequestDocs` 渲染；
  - 只有待办文件底部有办理依据与批准/退回；
  - 其他材料窗口没有批准/退回；
  - 拖动范围与卷宗一致：材料可从材料架拖到上半桌面，已打开的文件也能拖到学生信息/微信区上方（y=64 起），不再卡在 368 以下；
  - 长材料正文带“滚轮翻页 N%”提示，滚动时实时更新。
- 盖章图层：
  - 墨迹改为 `stamp_target` 的子节点并裁切在印章台内，不再出现在材料/卷宗/右栏图层；第二张材料压上来时会遮住第一张留下的墨迹，不会印到第二张上；

  - 材料压住印章台或在材料上松手时拒绝盖章并提示；
  - 待办文件批准/退回不再生成桌面粒子，只保留文件关闭 + Toast + 音效；批准/退回使用不同的合成提示音；
  - 批准/退回在文件底部生成局部章（文件子节点），停留约 0.26 秒后随文件关闭；headless 测试立即关闭。
- 材料与提示清理：
  - 材料卡和材料内部不再出现棉纸证书/牛皮卡纸/复写纸/密封存档/油印公示等材质名；
  - 单字图标改为线稿图标（请假、就诊、成绩、公告、护照、实习、实验室等）；
  - 去掉“对话结束·可盖章”“归位 R”“或先点印章”“拖出查看·拖回即收”“松手展开”等提示。
- 批准 / 退回：
  - `Noto Serif SC 700` 16px，字距 2px；
  - 128×44 / 124×44，深色边框 + 2px 阴影；
  - `A` 批准、`R` 退回、`Esc` 收起；
  - 大字号模式下按钮随字号增高。

### 3.1 新增材料样式

在原有五种纸张外新增八种，共 **13 种**：

- `student_id` 学生证：冷青证件带、照片位、磁条；
- `id_card` 身份证 / 证件卡：浅蓝底、证件字段；
- `scholarship` 奖学金证书：金线、衬线标题、校印；
- `admission` 录取通知书：绿色信头、正文与落款，适合国内外 offer；
- `ledger` 财务 / 助学金台账：绿色横线、金额栏；
- `index_card` 档案 / 图书馆卡：牛皮索引卡、红标题线；
- `passport` 护照 / 签证页：深蓝证件带、照片位；
- `boarding` 登机牌 / 凭证：热敏纸、虚线撕口。

这些样式都可以在编辑器的“待办包 → 材料 → 纸张样式”里直接选择；游戏内渲染见 [70-style-gallery.png](../screenshots/70-style-gallery.png)。更完整的中/外大学材料清单见 [`V1.13-MATERIALS.md`](V1.13-MATERIALS.md)。

## 4. 模块化内容

`content/` 现在是源文件：

```text
world.json       规则、页签、常备材料、结局、夜班
characters.json  人物姓名/学号/学院/专业/班级/导师/立绘
cases.json       论文题目/摘要/参考文献/查重/审查表/正文
levels.json      7 天 + 有序队列 + 待办挂接
tasks.json       12 个材料包（含交换/实验室/实习）
logic.json       条件链（编辑器侧，暂不编译进游戏）
```

- 人物身份只有一个来源；封面和查重报告的身份在构建时派生。
- 3 个故意做错的案例保留 `cover.overrides` / `dup.overrides`（封面学号、封面专业、报告学号），改名不会抹掉缺陷。
- `tools/content_tools.py`：`split` / `build` / `validate` / `check`。
- `check` 已加入 `tools/run_tests.ps1`，content 与 assets 不同步会阻断测试。

## 5. 关卡编辑器

`tools/level-editor/`：

- 概览：七日流程、统计、校验摘要。
- 关卡：元数据、人物/案例/待办三个下拉、拖拽排序、流程预览。
- 人物：搜索、立绘、身份字段、引用位置、论文案例、个案覆盖、高级 JSON。
- 待办包：办理依据、材料列表、字段/表格/段落/落款/印章、实时纸张预览。
- 条件链：START / 条件 / ALL / ANY / NOT / SET / 结果；拖节点、连 TRUE/FALSE、上下文试算、循环与不可达校验。
- 条件链画布：缩放/平移/minimap、撤销重做、复制粘贴、多选、自动布局、节点/链搜索、错误节点标红并可从校验页跳转。
- 学生消息：人物 → 论文案例底部可编辑 `line` 主消息和 `chat` 自定义序列（每行一条；留空自动生成）。
- 对话树：`case.dialogue` 支持学生/老师/自动/旁白说话人、每节点最多 4 个回复、回复指向后续节点，可连续分支；游戏内到达选项才显示按钮，选完沿分支继续。
- 纸张样式：13 种 stock 缩略图选择器、排版令牌、真实字段/表格/落款/印章预览。
- 保存：保存前 diff（文件/行数增删）、localStorage best-effort 自动保存与恢复。
- 校验 / 发布：阻断/提醒、构建摘要、保存 content、导出 assets。

支持两种工作方式：

- 本地服务器（推荐）：`python -m http.server 8899`，打开 `/tools/level-editor/`，自动读取 content，保存时下载 JSON。
- 选择项目根目录：Chrome/Edge 下可直接写回 `content/` 与 `assets/`。

编辑器内置的 JS 编译与 Python 构建规则一致；用现有 7 天内容对比，`data.json` 与 `requests.json` 语义完全相等。

## 7. 已知限制

- 同一学生有多份待办时，办结第一份后不会自动打开第二份；需要再点材料架里的下一份。
- 编辑器预览是结构预览，不等于 Godot 最终排版；以游戏截图和 `shotregress` 为准。
- 文件夹写回依赖 File System Access API；Firefox 只能下载 JSON。
- 直接双击 HTML 不会自动读取本地文件，需要本地服务器或手动选择文件夹/文件。
- 存档仍是每天早晨；当天已办结的待办不会跨读档保存。
- 条件链目前只在编辑器侧保存/试算，尚未编译进 `assets/` 或接入游戏运行时。
